Soak test, 2026-10-01/02 (tests/load/soak.py 45), demo stack on a 16-vCPU laptop: 5,000 events/s base with 3x
(15,000/s) bursts for 10 s every 2 minutes, 4 processor replicas, fresh database, sampled every ~35 s.

Findings
- Throughput held for 45 min: 15.8M events processed, 5,823/s average, no crashes or restarts, zero errors.
- Freshness p50 192 ms all the way through (target < 2 s). For the first ~24 min bursts were absorbed within one sample
  (freshness < 0.75 s). After that the current hour's telemetry partition grows past the Postgres cache
  (shared_buffers 512 MB, two vin-leading indexes), bursts back up for 30-60 s, and freshness spikes to 3-10 s
  (p95 7.9 s) before recovering. The next hourly partition starts small again.
- Processor memory 575 -> 672 MB average (first vs second half): Bloom filter and reorder buffer are bounded; the
  rest is allocator growth. API memory flat (~320 MB).
- Database grew 420 MB -> 3.9 GB: 45 min is shorter than the 2 h raw retention window, so no partition was due to
  be dropped yet. Retention dropping old partitions is covered by the batch logs ("retention: dropped N partitions").
Next steps: merge the two telemetry indexes into one unique (vin, ts, seq) index, raise shared_buffers, and
ultimately move raw telemetry to a columnar store (ADR-0002).
